## Method and results

Four process-balanced epochs cover B1 and B4. Epochs 1 and 3 ran
manager-before-stock; epochs 2 and 4 ran stock-before-manager. Each fresh
process records five iterations. The steady diagnostic excludes iteration 0,
leaving 16 hot samples per mode and batch. Percentiles below use Python
`statistics.quantiles(n=100, method="inclusive")`.

| B1 | 2.629672318 / 2.537401138 / 3.072171242 | 2.803181489 / 2.645168338 / 3.336977801 | +6.598129% | -6.189723% |
| B4 | 2.957611923 / 2.960283630 / 3.000194114 | 3.039595005 / 3.034505628 / 3.080026492 | +2.771935% | -2.697171% |

The per-epoch manager-over-stock latency deltas are B1 `+2.782217%`,
`+0.712922%`, `+26.340663%`, and `-1.983507%`; B4 `+1.844141%`,
`+2.885017%`, `+5.006971%`, and `+1.388493%`. The B1 aggregate is visibly
affected by noisy epochs 3 and 4, reinforcing the diagnostic-only boundary.

Every one of the eight pair artifacts was generated by the current
`integrations/sglang/qualify_abi8_h20.py::verify_pair_files` implementation
without a preflight record. All pairs pass exact token equality. Each of the
eight manager records has successful global cleanup, zero fail-stop/quarantine
counters, a fully drained token pool, and a fully drained fixed-state pool.

Stock and manager use the same capacity and report the same KV-cache memory:
B1 is 1,024 Full tokens and 0.063 GB; B4 is 4,096 Full tokens and 0.251 GB.
The observed equal configured tensor-arena reservation difference is therefore
**0%**. This is not a qualified end-to-end memory-saving result.

All 16 stderr logs show completion of 66/66 shard loading. They also each
contain two Transformers `use_fast` deprecation lines and PyTorch's
`CudaIPCTypes` producer-exit warning. No traceback, OOM, or explicit error is
present; the warning remains disclosed as residual process-teardown noise.

## Scope and verification

This package contains exactly 16 raw JSON records and 16 stderr logs copied
byte-for-byte at packaging time from
`/tmp/orbitkv-qwen38-h20-20260824/steady`, plus eight derived pair JSON files
and the four top-level package files. The manifest records a canonical digest
of the original 32-file path/size/hash inventory; portable verification can
only verify the retained copies because the temporary source tree is not part
of the package. `manifest.json` hashes every retained file except itself to
avoid a self-referential digest and declares the exact file/directory
inventory. `verify.py` rejects duplicate
JSON keys, non-finite values, unsafe paths, symlinks, missing or extra files,
hash/size drift, and identity drift. It calls the current pair verifier for all
eight pairs and recomputes token equality, execution order, hot timings,
capacity/memory parity, stderr observations, and final census/drain state.

Because the run-bound adapter inventory came from a dirty OrbitKV worktree,
the verifier uses `verify_pair_files`' explicit offline `harness_sha256` and
`adapter_identity` inputs. It also pins the current pair-verifier file hash.
This is intentionally weaker than a clean-source bundle plus preflight and is
why the archive cannot be promoted to a seal or qualification.

Run from the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 \
  results/h20-sglang-v0517-abi8-qwen38-fp8-diagnostic-20260824/verify.py
```

The verifier is read-only and emits one JSON result on success.
